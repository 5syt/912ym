# 旅游助手智能体 - 工作流（对话流）设计说明

## 一、整体架构

旅游助手智能体采用"意图识别-知识调用-多模态输出"的技术链路，通过对话流实现用户旅游咨询的智能化处理。对话流共包含 **11个节点**，调用 **3次大模型**，使用 **知识库检索** 和 **代码节点** 处理数据。

### 对话流整体结构

```
开始节点
    ↓
意图识别节点 ──────┬────── 旅游相关问题 ────── 大模型1（问题理解/改写）
    │              │                                    ↓
    │              │                              知识库检索节点
    │              │                                    ↓
    │              │                              大模型2（客服回复/总结）
    │              │                                    ↓
    │              │                              代码节点（格式转换）
    │              │                                    ↓
    │              │                              添加记录节点（存对话记录）
    │              │                                    ↓
    │              │                              输出节点1（回复用户）
    │              │                                    ↓
    │              └───────────────────────────────────┤
    │                                                  │
    └──────────── 非旅游相关问题 ────── 大模型3（闲聊/通用）
                        ↓                        ↓
                   输出节点2 ──────────────── 结束节点
```

## 二、节点详细配置

### 节点1：开始节点

- **节点名称**：开始节点
- **节点类型**：开始节点
- **功能描述**：对话流入口，接收用户输入
- **配置说明**：
  - 输入变量：`USER_INPUT`（用户输入的文本消息）
  - 输出变量：无

### 节点2：意图识别节点

- **节点名称**：意图识别节点
- **节点类型**：意图识别节点
- **功能描述**：识别用户问题的意图类型，分发到不同处理分支
- **配置参数**：
  - **输入变量**：
    - 变量名：`query`
    - 变量值：引用开始节点的 `USER_INPUT`
  - **意图分类**（2条）：
    1. **旅游相关问题**
       - 描述：用户咨询旅游相关的问题，包括景点、美食、住宿、交通、路线规划、旅游攻略等
       - 触发示例："北京有什么好玩的景点？"、"去三亚旅游住哪里好？"、"成都美食推荐"
    2. **非旅游相关问题**
       - 描述：与旅游无关的闲聊、日常问题或其他话题
       - 触发示例："你好"、"今天天气怎么样"、"你叫什么名字"

### 节点3：大模型1节点（问题理解与改写）

- **节点名称**：大模型_1节点
- **节点类型**：大模型节点
- **功能描述**：结合对话上下文，准确理解用户问题，必要时对问题进行改写，便于后续知识库检索
- **模型选择**：DeepSeek V3.1（或其他可用大模型）
- **配置参数**：
  - **输入变量**：
    - `query`：用户当前问题（来自开始节点）
    - `history`：对话历史记录
  - **系统提示词**：见 `prompts/rewrite_prompt.md`
  - **用户提示词**：
    ```
    对话历史：{{history}}
    用户当前问题：{{query}}
    请结合上下文理解并改写用户问题。
    ```
  - **输出变量**：`rewritten_query`（改写后的问题）

### 节点4：知识库检索节点

- **节点名称**：知识库节点
- **节点类型**：知识库节点
- **功能描述**：根据改写后的问题，从知识库中检索相关内容
- **配置参数**：
  - **输入变量**：
    - 搜索词：`{{rewritten_query}}`（引用大模型_1节点的输出）
  - **知识来源**（2个知识库）：
    1. **旅游攻略知识库**（文档型）
       - 来源：本地上传的 Word/PDF 文档
       - 内容：景点介绍、美食攻略、住宿推荐、交通指南等
    2. **旅游FAQ知识库**（表格型）
       - 来源：表格导入
       - 索引字段：常见问题
       - 内容：常见旅游问题及标准答案
  - **检索设置**：
    - 召回条数：5条
    - 相似度阈值：0.7

### 节点5：大模型2节点（客服回复生成）

- **节点名称**：大模型节点
- **节点类型**：大模型节点
- **功能描述**：根据知识库召回的内容，生成专业、友好的旅游咨询回复
- **模型选择**：DeepSeek V3.1
- **配置参数**：
  - **输入变量**：
    - `input`：用户原始问题
    - `respond`：知识库检索结果
  - **系统提示词**：见 `prompts/travel_assistant_prompt.md`
  - **用户提示词**：
    ```
    用户咨询：{{input}}
    知识库匹配结果：{{respond}}
    请根据知识库内容给用户回复。
    ```
  - **输出变量**：`bot_reply`（AI生成的回复内容）

### 节点6：代码节点

- **节点名称**：代码节点
- **节点类型**：代码节点
- **功能描述**：将用户问题和AI回复转换为对话记录表格所需的数组格式
- **编程语言**：JavaScript
- **输入变量**：
  - `user`：用户问题
  - `bot`：AI回复内容
- **输出变量**：`records`（格式化后的记录数组）
- **代码内容**：见 `code/code_node.js`

### 节点7：添加记录节点（add_records）

- **节点名称**：add_records节点
- **节点类型**：添加记录节点（数据库/多维表格插件）
- **功能描述**：将对话记录保存到数据表中，用于后续数据分析和FAQ积累
- **配置参数**：
  - **数据表**：对话记录表
  - **输入数据**：引用代码节点输出的 `records`
  - **字段映射**：
    - 用户问题 → 用户问题字段
    - Bot回复 → Bot回复字段
    - FAQ → 默认值"否"

### 节点8：输出节点1

- **节点名称**：输出1节点
- **节点类型**：输出节点
- **功能描述**：将旅游相关问题的AI回复输出给用户
- **配置参数**：
  - 输出内容：引用大模型节点输出的 `bot_reply`
  - 输出类型：文本

### 节点9：大模型3节点（非旅游问题处理）

- **节点名称**：大模型_2节点
- **节点类型**：大模型节点
- **功能描述**：处理与旅游无关的闲聊或通用问题
- **模型选择**：DeepSeek V3.1
- **配置参数**：
  - **输入变量**：
    - `query`：用户问题
  - **系统提示词**：见 `prompts/chat_prompt.md`
  - **用户提示词**：
    ```
    用户说：{{query}}
    请友好回复。
    ```
  - **输出变量**：`chat_reply`

### 节点10：输出节点2

- **节点名称**：输出节点
- **节点类型**：输出节点
- **功能描述**：输出非旅游相关问题的回复
- **配置参数**：
  - 输出内容：引用大模型_2节点输出的 `chat_reply`
  - 输出类型：文本

### 节点11：结束节点

- **节点名称**：结束节点
- **节点类型**：结束节点
- **功能描述**：对话流结束
- **配置参数**：
  - 返回输出变量：否
  - 结束文本："请问还有其他旅游问题需要咨询吗？"

## 三、数据流说明

1. 用户输入问题 → 开始节点
2. 意图识别 → 判断是旅游相关还是非旅游相关
3. **旅游相关分支**：
   - 大模型1改写问题 → 知识库检索 → 大模型2生成回复 → 代码节点格式化 → 保存记录 → 输出回复
4. **非旅游相关分支**：
   - 大模型3直接回复 → 输出回复
5. 结束节点 → 询问是否继续

## 四、知识库设计

### 知识库1：旅游攻略知识库（文档型）

- **类型**：文档知识库
- **内容来源**：上传Word/PDF文档
- **内容分类**：
  - 景点介绍（各城市热门景点、门票、开放时间）
  - 美食攻略（特色美食、推荐餐厅）
  - 住宿推荐（不同价位酒店、民宿）
  - 交通指南（交通方式、路线建议）
  - 旅行贴士（注意事项、最佳旅游季节）

### 知识库2：旅游FAQ知识库（表格型）

- **类型**：表格知识库
- **数据来源**：表格导入
- **表结构**：
  | 字段名 | 类型 | 说明 | 是否索引 |
  |--------|------|------|----------|
  | 常见问题 | 文本 | 用户常见问题 | 是 |
  | 标准答案 | 文本 | 对应回答 | 否 |
  | 分类 | 文本 | 问题分类（景点/美食/住宿等） | 否 |
- **更新频率**：每日同步
- **索引字段**：常见问题

## 五、对话记录表设计

### 表名：对话记录表

| 字段名 | 类型 | 说明 |

### FAQ表

|--------|------|------|

| 标准答案 | 文本 | 对应回答 |
| 分类 | 文本 | 问题分类 |
| 添加时间 | 日期 | 添加时间 |
