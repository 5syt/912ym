## 1 需求分析

### 1.1 项目背景和意义

随着大语言模型技术的快速发展，智能客服和智能助手已成为生成式AI的典型应用场景之一。在旅游行业，传统的旅游咨询方式存在信息分散、服务效率低、个性化不足等问题。基于大模型的旅游助手智能体能够整合海量旅游信息，为用户提供7×24小时的智能化咨询服务，极大地提升旅游咨询的效率和用户体验。

扣子平台作为一个低代码AI应用开发平台，不仅集成了丰富的大语言模型供选择，可快速构建问答能力，其开放能力和丰富的AI应用搭建功能更是极大地简化了智能体的搭建和维护成本。本项目基于扣子平台，构建一个功能完整的旅游助手智能体，旨在为用户提供专业、便捷、个性化的旅游咨询服务。

与传统的旅游攻略网站相比，基于AI的旅游助手具有以下优势：
- **自然语言交互**：用户可以用自然语言提问，无需学习复杂的搜索语法
- **个性化推荐**：根据用户需求提供定制化的旅游建议
- **多轮对话能力**：支持上下文理解，进行深入的旅游规划讨论
- **持续学习优化**：通过不断积累用户问题，持续优化知识库和回答质量

### 1.2 项目主要功能

基于扣子平台，构建一个功能完整的旅游助手智能体系统。核心目标包括：

（1）通过意图识别、知识库检索、大模型回复生成等技术，实现对用户旅游问题的智能处理；

（2）通过与多维表格的集成，实现对对话数据的记录和FAQ知识库的自动更新；

（3）系统不仅能够提高旅游咨询效率，还能不断学习和优化，随着时间推移，为用户提供越来越精准的旅游服务。

具体功能包括：
- 景点推荐与介绍
- 美食攻略推荐
- 住宿建议
- 交通指南
- 行程规划
- 旅行贴士
- FAQ自助查询
- 对话记录与数据分析
- 知识库动态更新

### 1.3 目标用户

本系统的目标用户主要包括以下几类：

**普通游客**：计划出行或正在旅途中的游客，希望通过智能助手快速获取旅游信息、解答旅行疑问、规划行程路线等。

**旅游从业者**：旅行社、酒店等旅游行业从业人员，借助智能助手系统辅助回答客户常见问题，提升服务效率，降低人工负荷。

**产品运营人员**：负责旅游产品推广与用户调研的相关人员，通过系统收集用户反馈与高频问题，优化产品与服务策略。

**系统管理员**：负责智能体系统的部署、维护与迭代优化，确保系统稳定运行并持续提升服务能力。

### 1.4 使用场景

本系统适用于以下典型场景：

（1）**景点咨询**：用户询问某个城市有哪些必去景点、景点门票价格、开放时间、游玩攻略等信息。

（2）**美食推荐**：用户想了解当地特色美食、推荐餐厅、美食街等信息。

（3）**行程规划**：用户有几天时间，希望获得合理的旅游行程安排建议。

（4）**住宿交通**：用户咨询住在哪里方便、怎么去某个景点最便捷等问题。

（5）**FAQ自助查询**：用户通过自然语言提问，系统自动匹配知识库中的常见问题并给出标准答案。

（6）**对话记录与数据分析**：运营人员可通过多维表格查看历史对话记录，分析用户需求热点，优化服务内容。

（7）**知识库动态更新**：系统自动将高频或典型对话记录标记为FAQ，同步更新至知识库，实现知识持续积累与共享。

## 2 系统设计

### 2.1 设计思路

本项目旅游助手智能体以**用户需求**为核心，通过"意图识别-知识调用-多模态输出"的技术链路，结合"场景适配-生态协同"的运营逻辑，实现"精准响应、持续迭代、生态联动"的智能体能力。

#### 设计思路整体架构

1. **用户交互与意图识别**：构建"意图-响应"闭环

该智能体以旅游助手"小旅"为交互起点，通过**用户意图识别**模块解析用户需求。该模块具备：
- **意图分类能力**：将用户需求拆解为"旅游相关问题"和"非旅游相关问题"两大维度，为后续知识调用提供精准方向。

2. **知识调用与融合**：构建"知识-场景"映射

意图识别后，智能体通过**知识调用**模块实现"需求-知识"的精准匹配，核心设计亮点包括：
- **知识库分层与动态更新**：文档知识库沉淀通用旅游知识，支持"旅游相关问题"的基础响应；FAQ表格知识库聚焦高频问题，持续迭代优化。
- **大模型理解与生成**：通过大模型进行问题改写和回答生成，提升回复质量。

3. **场景适配与流程闭环**：保障"需求-结果"一致性

智能体设计还覆盖**场景适配**与**流程闭环**两大维度：
- **场景适配**：针对"旅游相关问题"和"非旅游相关问题"等不同场景，智能体通过不同处理路径，确保响应的场景适配性。
- **流程闭环**：从"用户查询"到"最终输出"，智能体通过"用户意图识别→知识调用→回复生成→记录存储"的流程，实现"需求发起→需求解析→需求响应→数据沉淀"的完整闭环。

4. **数据与知识协同**：强化"智能体-数据"联动

智能体设计还融入**数据协同**逻辑：通过多维表格记录对话数据，反向优化知识库，形成"需求→响应→优化"的生态闭环。

### 2.2 工作流（或对话流）设计

扣子对话流整体结构共添加了**11个节点**，**3次调用大模型**，使用了**知识库节点**和**代码节点**以及**添加记录节点**。

#### 对话流节点列表

| 序号 | 节点名称 | 节点类型 | 功能简介 |
|------|----------|----------|----------|
| 1 | 开始节点 | 开始节点 | 对话流入口，接收用户输入 |
| 2 | 意图识别节点 | 意图识别节点 | 识别用户意图，分发到对应处理分支 |
| 3 | 大模型_1节点 | 大模型节点 | 结合上下文理解并改写用户问题 |
| 4 | 知识库节点 | 知识库节点 | 根据改写后的问题检索相关知识 |
| 5 | 大模型节点 | 大模型节点 | 基于知识库内容生成旅游咨询回复 |
| 6 | 代码节点 | 代码节点 | 格式化对话记录数据 |
| 7 | add_records节点 | 添加记录节点 | 将对话记录保存到多维表格 |
| 8 | 输出1节点 | 输出节点 | 输出旅游相关问题的回复 |
| 9 | 大模型_2节点 | 大模型节点 | 处理非旅游相关问题 |
| 10 | 输出节点 | 输出节点 | 输出非旅游问题的回复 |
| 11 | 结束节点 | 结束节点 | 对话流结束 |

#### 工作流程说明

**旅游相关问题处理流程**：
1. 用户输入问题
2. 意图识别节点判断为旅游相关问题
3. 大模型_1节点结合上下文改写问题
4. 知识库节点检索相关旅游知识
5. 大模型节点基于知识库内容生成回复
6. 代码节点将问题和回复格式化为记录数组
7. add_records节点将记录保存到对话记录表
8. 输出1节点将回复呈现给用户
9. 结束节点

**非旅游相关问题处理流程**：
1. 用户输入问题
2. 意图识别节点判断为非旅游相关问题
3. 大模型_2节点直接生成友好回复
4. 输出节点将回复呈现给用户
5. 结束节点

### 2.3 数据库设计

#### 2.3.1 对话记录表

对话记录表的核心目的在于通过系统化收集和管理用户对话数据，优化运营效率并提升服务质量。具体目的包括：

**提供个性化服务**：通过记录用户偏好和咨询历史，智能体能更好地理解用户需求，提供更个性化的推荐。

**支持精准运营**：基于用户历史行为和问题类型，运营人员可定向优化知识库内容，提高服务质量。

**促进知识积累**：通过持续记录互动内容，将高频优质问答标记为FAQ，丰富知识库。

**优化产品决策**：整合用户问题数据生成分析报告，帮助识别热门旅游目的地和用户痛点，辅助产品策略调整。

**简化运营流程**：集中管理对话信息，实现信息实时检索和统计分析，提高运营效率。

#### 2.3.2 表结构设计

**对话记录表**：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 用户问题 | 多行文本 | 用户提问的内容 |
| Bot回复 | 多行文本 | AI智能体的回复内容 |
| 是否FAQ | 单选 | 是否标记为FAQ（是/否），默认"否" |
| 提问时间 | 日期 | 用户提问时间 |
| 问题分类 | 单选 | 问题类型分类（景点/美食/住宿/交通/行程/贴士/其他） |

**FAQ知识库表**：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 常见问题 | 多行文本 | 用户常见问题（索引字段） |
| 标准答案 | 多行文本 | 对应回答 |
| 分类 | 单选 | 问题分类 |
| 添加时间 | 日期 | 添加到FAQ的时间 |

### 2.4 知识库设计

本项目有两个知识库，一个是基于文档的旅游攻略知识库，用于存储各城市详细的旅游信息，另一个是基于表格的FAQ知识库，用于存储用户常见问题及标准答案。

#### 知识库1：旅游攻略知识库（文档型）

- **类型**：文档知识库
- **数据来源**：本地上传的Word/Markdown文档
- **内容涵盖**：
  - 北京、上海、成都、西安、厦门、三亚、杭州、重庆等热门城市的旅游攻略
  - 每个城市包含：景点推荐、美食推荐、住宿建议、交通指南、最佳旅游时间
  - 通用旅游贴士
- **处理方式**：扣子平台自动切片、向量化
- **更新方式**：手动上传更新文档

#### 知识库2：旅游FAQ知识库（表格型）

- **类型**：表格知识库
- **数据来源**：表格导入
- **表结构**：常见问题、标准答案、分类
- **索引字段**：常见问题
- **更新频率**：每日同步（或按需同步）
- **内容**：50+条常见旅游问题及标准答案

#### 知识库联动机制

当对话记录表中的某条记录被标记为FAQ时，通过自动化流程自动同步到FAQ知识库表，实现知识库的持续积累和自动更新。

### 2.5 多平台协同交互设计

本系统通过扣子平台与多维表格的深度集成，实现跨平台数据流转与业务协同，具体设计如下：

#### （1）数据同步机制

多维表格作为中心数据存储层，记录所有用户与智能体的对话内容。
当对话被标记为"FAQ"时，系统自动触发自动化流程，将记录同步至FAQ表。
扣子平台通过知识库同步功能实时拉取FAQ表数据，更新本地知识库，确保回答的时效性与准确性。

#### （2）流程触发与响应

用户在扣子平台发起咨询后，系统通过意图识别模块判断问题类型。
若为旅游相关问题，系统调用知识库与表格数据，生成回答并同步记录至对话记录表。
若为非旅游问题，则由大模型直接生成回复。

#### （3）权限与安全管理

表格的访问与编辑权限通过平台统一管理，支持按角色分配查看、编辑等权限。
扣子平台通过授权方式获取数据访问权限，确保数据调用的安全性与合规性。

#### （4）协同工作流

运营人员可在表格中直接查看对话记录、用户反馈与FAQ更新情况。
系统管理员可通过自动化流程配置，如定时同步数据、发送报表通知等。
产品团队可根据表格中的用户问题统计，优化知识库内容与服务话术，形成"用户反馈→系统响应→知识更新"的闭环协同流程。

## 3 开发实现

### 3.1 多维表格配置

#### 3.1.1 创建数据表

在多维表格平台创建两个数据表：
1. **旅游助手对话记录表**：记录智能体与用户的所有对话
2. **旅游FAQ知识库**：存储常见问题及标准答案

#### 3.1.2 配置字段

按照2.3节的表结构设计，配置各表的字段名称、类型和选项。

#### 3.1.3 配置自动化流程

设置自动化流程：当"旅游助手对话记录表"中"是否FAQ"字段变为"是"时，自动在"旅游FAQ知识库"表中新增一条记录。

自动化流程配置步骤：
1. 新建自动化流程
2. 设置触发器：当记录内容变更时
   - 触发表：旅游助手对话记录表
   - 触发条件：是否FAQ 变更为 是
3. 添加操作：新增记录
   - 目标表：旅游FAQ知识库
   - 字段映射：
     - 常见问题 = 触发记录的用户问题
     - 标准答案 = 触发记录的Bot回复
     - 分类 = 触发记录的问题分类
     - 添加时间 = 当前时间

### 3.2 准备扣子知识库

#### 3.2.1 创建文档知识库

1. 登录扣子平台，进入知识库页面
2. 点击"创建知识库"，选择"文档"类型
3. 命名为"旅游攻略知识库"
4. 上传准备好的旅游攻略文档（支持Word、PDF、Markdown等格式）
5. 等待平台自动处理文档内容
6. 验证知识库内容是否正确

#### 3.2.2 创建表格知识库

1. 在知识库页面点击"创建知识库"，选择"表格"类型
2. 命名为"旅游FAQ知识库"
3. 选择"从表格导入"数据
4. 导入前面创建好的多维表格中的FAQ表
5. 按照提示完成授权和数据导入
6. 设置知识库表结构，将"常见问题"字段设置为索引字段
7. 设置知识库更新频率，如"每日更新"，确保多维表格中的FAQ数据能及时同步到扣子平台

### 3.3 对话流实现

#### 3.3.1 创建对话流

1. 登录扣子官方网站，在主页面左侧菜单中，依次点击"工作空间"→"资源库"
2. 在打开的资源库页面中，点击"+资源"按钮，在弹出的快捷菜单中点击"对话流"
3. 在"创建对话流"窗口中，将对话流命名为"travel-assistant"
4. 在描述栏中填写"旅游助手智能体，为用户提供专业的旅游咨询服务"
5. 点击确定，进入对话流编辑页面

#### 3.3.2 问题意图识别配置

1. 在对话流编辑页面，添加"意图识别"节点
2. 将开始节点连接到意图识别节点
3. 在意图识别节点的配置窗口中进行参数配置：
   - 输入区域：设置变量名为query，变量值引用来自开始节点的USER_INPUT
   - 意图匹配添加两条：
     - 第一条："旅游相关问题"，描述用户咨询景点、美食、住宿、交通、行程等旅游相关问题
     - 第二条："非旅游相关问题"，描述与旅游无关的闲聊或其他问题

#### 3.3.3 旅游相关问题处理模块

处理旅游相关问题的路线：大模型参考历史对话改写用户的查询Query，再根据Query检索知识库，由另一个大模型进行总结和输出，用户Query及大模型回复均通过添加记录节点保存在多维表格中。

**步骤1：添加大模型_1节点（问题改写）**
- 在意图识别节点的"旅游相关问题"分支后添加大模型节点
- 命名为"大模型_1"
- 配置输入参数：query（用户问题）
- 配置系统提示词：问题理解与改写提示词
- 配置用户提示词：
  ```
  用户当前问题：{{query}}
  ```

- **输入**："成都有什么好吃的？"

- **验证点**：回答内容丰富，符合成都特色

#### 测试用例3：行程规划（旅游相关）
- **输入**："3天时间在厦门怎么玩？"
- **预期输出**：给出厦门3日游的行程安排建议

- **验证点**：意图识别正确，进入非旅游分支，回复友好

#### 测试用例5：对话记录保存
- **操作**：提问一个旅游相关问题
- **预期结果**：对话记录表中新增一条记录，包含用户问题和AI回复
- **验证点**：数据正确保存到多维表格

#### 测试用例6：FAQ标记与同步
- **操作**：在对话记录表中将某条记录的"是否FAQ"改为"是"
- **预期结果**：FAQ知识库表中自动新增对应记录
- **验证点**：自动化流程触发成功，数据同步正确

### 4.2 测试结果

经过全面测试，旅游助手智能体基本能够满足用户需求，系统无阻塞性bug，能达到项目的预期效果。主要测试结果如下：

#### 旅游相关问题测试结果
- 景点咨询：能准确推荐各城市热门景点，回答包含门票、开放时间等实用信息
- 美食推荐：能根据城市推荐当地特色美食和餐厅
- 行程规划：能根据天数给出合理的行程安排建议
- 交通住宿：能提供实用的交通和住宿建议
- 知识库检索：召回结果准确，与用户问题高度相关

#### 非旅游相关问题测试结果
- 能正确识别非旅游问题，进入闲聊分支
- 回复友好礼貌，并能引导用户回到旅游话题

#### 对话记录测试结果
- 对话记录表能正确保存每一条旅游相关对话
- 字段映射正确，用户问题和AI回复都能准确记录

#### FAQ同步测试结果
- 当对话记录被标记为FAQ时，能自动同步到FAQ知识库表
- 扣子平台的FAQ知识库能定时同步最新数据
- 形成了"对话→标记→同步→知识库更新"的完整闭环

#### 发现的问题与优化
1. **问题**：部分冷门旅游问题知识库中没有相关内容
   **优化**：持续扩充知识库内容，增加更多城市和景点的介绍

2. **问题**：多轮对话上下文理解有时不够准确
   **优化**：优化问题改写提示词，提升大模型对上下文的理解能力

3. **问题**：回复长度有时过长
   **优化**：在提示词中进一步强调简洁性，控制回答字数

## 5 项目总结

通过本次基于扣子平台的旅游助手智能体开发，我深入学习了大模型应用开发的全流程，从需求分析、系统设计到开发实现、测试优化，全面掌握了智能体开发的核心技能。

### 项目成果
1. 成功构建了一个功能完整的旅游助手智能体，涵盖景点推荐、美食攻略、行程规划等多个旅游场景
2. 设计并实现了包含11个节点的对话流，集成了意图识别、知识库检索、大模型生成、代码节点等多种能力
3. 搭建了文档+表格双知识库体系，实现了知识库的动态更新和持续积累
4. 通过多维表格集成，实现了对话记录的自动保存和FAQ的自动同步

### 技术收获
1. 掌握了扣子平台的使用方法，包括对话流设计、知识库搭建、插件集成等
2. 深入理解了RAG（检索增强生成）技术的原理和应用
3. 学会了如何编写高质量的提示词，提升大模型的回答质量
4. 了解了智能体开发的完整流程和最佳实践

### 不足与展望
1. 当前知识库仅覆盖了8个热门城市，后续可以继续扩充更多城市和更丰富的旅游信息
2. 可以增加更多功能，如天气查询、机票酒店查询、翻译等，提升智能体的实用性
3. 可以尝试接入更多平台，如微信、抖音等，扩大智能体的服务范围
4. 可以增加数据分析功能，通过用户对话数据挖掘用户需求，持续优化服务

通过这次项目实践，我深刻体会到大模型技术在旅游行业的巨大应用价值。未来随着技术的不断进步，智能旅游助手必将为用户带来更加便捷、个性化的旅游体验。
