## 1. 绪论

### 1.1 项目背景

随着互联网技术的快速发展，Web应用的规模和复杂度不断增加，传统的手工测试已经难以满足现代软件开发的效率和质量要求。自动化测试作为软件测试领域的重要技术手段，能够通过脚本自动执行测试用例，提高测试效率、减少人为错误、保证测试的一致性和可重复性。

豆瓣读书（book.douban.com）是一个知名的图书信息分享平台，提供图书搜索、分类浏览、图书详情查看等功能。该网站结构稳定、功能清晰，非常适合作为Web自动化测试的学习和实践对象。通过对豆瓣读书进行自动化测试，可以掌握 Selenium WebDriver、pytest 框架、Page Object 设计模式等核心技术的实际应用。

### 1.2 研究的目的和意义

本项目旨在通过实际项目开发，系统学习和掌握以下核心知识与技能：

1. **Selenium WebDriver框架**：掌握浏览器自动化控制技术，能够模拟用户操作（打开网页、点击、输入、获取元素信息等）。

2. **pytest测试框架**：熟练运用pytest的参数化、fixture、钩子函数等功能，实现测试用例的高效组织和管理。

3. **Page Object设计模式**：理解并实践页面对象模型，将页面元素定位与业务逻辑分离，提高代码的可维护性和复用性。

4. **数据驱动思想**：实现测试数据与测试脚本的分离，使测试用例能够通过不同的测试数据重复执行，提高测试覆盖率。

5. **测试报告与日志**：掌握Allure报告生成和logging日志记录技术，能够清晰呈现测试结果和问题定位。

### 1.3 测试对象概述

本项目选取**豆瓣读书**（book.douban.com）作为被测对象，主要基于以下考虑：

- **网站稳定性**：豆瓣读书是成熟稳定的网站，页面结构相对固定，元素定位可靠性高。
- **反爬限制较少**：相比其他商业网站，豆瓣的反爬机制相对温和，适合自动化测试学习。
- **功能模块丰富**：包含搜索、分类浏览、详情查看等典型功能，覆盖多种Web交互场景。
- **公开可访问**：无需登录即可访问大部分功能，测试环境搭建简单。

### 1.4 测试范围

本项目的测试范围包括以下核心功能模块：

| 模块 | 功能描述 | 测试重点 |

## 3. 测试实现

### 3.1 核心代码展示与分析

#### 3.1.1 BasePage基类设计

BasePage是整个测试框架的基类，封装了所有常用的Selenium操作方法，所有Page类都继承自它。这种设计实现了代码的高度复用，避免了在每个Page类中重复编写元素定位和操作方法。

```python
"""
BasePage 基类
封装页面元素定位和常用操作的通用方法
所有页面类都需要继承此类
"""
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC
from selenium.webdriver.common.by import By
from common.logger import get_logger
from common.screenshot import save_screenshot

class BasePage:
    """页面对象基类"""

    def __init__(self, driver):
        """初始化基类

        Args:
            driver: WebDriver实例
        """
        self.driver = driver
        self.logger = get_logger()
        self.timeout = 10  # 默认显式等待超时时间

    def find_element(self, locator):
        """查找单个元素，使用显式等待

        Args:
            locator: 元素定位器元组，如(By.ID, "id_value")

        Returns:
            WebElement: 找到的元素对象
        """
        self.logger.info(f"查找元素: {locator}")
        try:
            element = WebDriverWait(self.driver, self.timeout).until(
                EC.visibility_of_element_located(locator)
            )
            self.logger.info(f"元素已找到: {locator}")
            return element
        except Exception as e:
            self.logger.error(f"查找元素失败: {locator}, 错误: {str(e)}")
            raise

    def click(self, locator):
        """点击元素，等待元素可点击后再点击

        Args:
            locator: 元素定位器元组
        """
        self.logger.info(f"点击元素: {locator}")
        element = self.wait_element_clickable(locator)
        element.click()
        self.logger.info(f"点击成功: {locator}")

    def input_text(self, locator, text):
        """输入文本，清除后输入新文本

        Args:
            locator: 元素定位器元组
            text: 要输入的文本
        """
        self.logger.info(f"向 {locator} 输入文本: {text}")
        element = self.find_element(locator)
        element.clear()
        element.send_keys(text)
        self.logger.info("文本输入成功")

    def wait_element_clickable(self, locator):
        """等待元素可点击

        Args:
            locator: 元素定位器元组

        Returns:
            WebElement: 可点击的元素对象
        """
        return WebDriverWait(self.driver, self.timeout).until(
            EC.element_to_be_clickable(locator)
        )
```

**设计思路分析：**

1. **显式等待机制**：所有元素操作都使用WebDriverWait显式等待，相比硬编码的time.sleep()更加稳定和高效，能够根据元素实际加载情况动态调整等待时间。

2. **日志记录**：每个方法都记录了操作前后的日志，便于问题追踪和测试过程回放。

3. **异常处理**：捕获异常后重新抛出，但保留了日志记录，便于定位问题。

4. **方法封装**：将常用的操作（查找、点击、输入）封装为独立方法，上层测试用例只需调用即可，无需关心底层实现。

#### 3.1.2 Page Object页面类实现

以首页为例，Page类负责封装该页面特有的元素定位和业务操作方法，与BasePage形成继承关系，体现了Page Object设计模式的核心思想。

```python
"""
HomePage 页面类
封装豆瓣读书首页的元素定位和业务操作
"""
from selenium.webdriver.common.by import By
from base.base_page import BasePage

class HomePage(BasePage):
    """豆瓣读书首页页面对象"""

    # 元素定位器
    SEARCH_INPUT = (By.ID, "inp-query")  # 搜索输入框
    SEARCH_BUTTON = (By.CSS_SELECTOR, ".search-button")  # 搜索按钮
    NAV_LITERATURE = (By.XPATH, "//a[@href='/tag/文学']")  # 文学分类导航

    def open(self):
        """打开豆瓣读书首页"""
        self.logger.info("打开豆瓣读书首页...")
        self.open_url("https://book.douban.com")
        self.logger.info("首页加载完成")

    def search_book(self, keyword):
        """搜索图书

        Args:
            keyword: 搜索关键词

        Returns:
            SearchResultPage: 搜索结果页面对象（供测试用例跳转）
        """
        self.logger.info(f"执行图书搜索，关键词: {keyword}")
        # 输入搜索关键词
        self.input_text(self.SEARCH_INPUT, keyword)
        # 点击搜索按钮
        self.click(self.SEARCH_BUTTON)
        self.logger.info("搜索操作完成")

        # 导入并返回搜索结果页对象
        from page.search_result_page import SearchResultPage
        return SearchResultPage(self.driver)

    def click_category(self, category_name):
        """点击分类导航

        Args:
            category_name: 分类名称

        Returns:
            CategoryPage: 分类页面对象
        """
        self.logger.info(f"点击分类导航: {category_name}")
        # 根据分类名称构建定位器
        locator = (By.XPATH, f"//a[contains(@href,'/tag/{category_name}')]")
        self.click(locator)
        self.logger.info("分类导航点击完成")

        # 导入并返回分类页对象
        from page.category_page import CategoryPage
        return CategoryPage(self.driver)
```

**设计思路分析：**

1. **元素定位器集中管理**：将元素定位器定义为类属性（如`SEARCH_INPUT`），使用元组格式`(By.ID, "inp-query")`，便于维护和修改。当页面结构变化时，只需修改定位器定义，无需改动业务逻辑代码。

2. **业务操作方法封装**：将用户的实际操作步骤封装为方法（如`search_book()`），返回对应的页面对象，实现页面间的链式调用。

3. **延迟导入**：在方法内部导入其他Page类，避免循环导入问题。

4. **PO模式优势**：测试用例不需要知道搜索框的ID是什么，只需要调用`home_page.search_book("三体")`即可完成搜索操作，代码更加清晰易读。

#### 3.1.3 数据驱动测试实现

数据驱动是自动化测试的重要思想，通过将测试数据与测试脚本分离，可以用一个测试方法执行多组测试数据，大大提高测试效率。

```python
"""
test_book_search.py - 图书搜索功能测试
使用数据驱动实现多组测试数据
"""
import pytest
import allure
from page.home_page import HomePage
from page.search_result_page import SearchResultPage
from common.logger import get_logger
from common.data_reader import read_json

logger = get_logger()
# 读取测试数据
TEST_DATA = read_json("search_data.json")

@pytest.mark.usefixtures("driver")
class TestBookSearch:
    """图书搜索功能测试类"""

    @pytest.mark.parametrize("test_case", TEST_DATA["test_cases"])
    @allure.feature("图书搜索")
    @allure.story("搜索功能测试")
    def test_search_book(self, driver, test_case):
        """测试图书搜索功能

        Args:
            driver: 浏览器驱动fixture
            test_case: 测试数据（来自JSON文件）
        """
        case_name = test_case["case_name"]
        keyword = test_case["keyword"]
        expect_has_result = test_case["expect_has_result"]

        with allure.step(f"执行测试用例: {case_name}"):
            logger.info(f"=" * 50)
            logger.info(f"开始执行: {case_name}")
            logger.info(f"=" * 50)

        with allure.step("1. 打开豆瓣读书首页"):
            home_page = HomePage(driver)
            home_page.open()

        with allure.step(f"2. 输入搜索关键词: {keyword}"):
            search_result_page = home_page.search_book(keyword)

        with allure.step("3. 验证搜索结果"):
            if expect_has_result:
                # 验证有结果的情况
                page_title = search_result_page.get_title()
                assert keyword in page_title, f"页面标题应包含'{keyword}'"
                logger.info(f"✓ 页面标题验证通过: {page_title}")

                titles = search_result_page.get_result_titles()
                assert len(titles) > 0, "搜索结果数量应大于0"
                logger.info(f"✓ 搜索到 {len(titles)} 条结果")

                # 验证第一个结果标题包含关键词
                first_title = titles[0]
                assert keyword in first_title, f"第一个结果应包含'{keyword}'"
                logger.info(f"✓ 第一个结果验证通过: {first_title}")
            else:
                # 验证无结果的情况
                is_empty = search_result_page.is_result_empty()
                logger.info(f"无结果验证: 页面显示无结果={is_empty}")

        with allure.step("4. 测试完成"):
            logger.info(f"✓ {case_name} 执行完成")
```

**设计思路分析：**

1. **数据外部化**：测试数据存储在JSON文件中，测试脚本只需要调用`read_json()`函数读取数据即可。当需要增加测试用例时，只需在JSON文件中添加数据，无需修改测试代码。

2. **pytest参数化**：`@pytest.mark.parametrize`装饰器实现数据驱动，第一个参数是参数名（与测试方法签名一致），第二个参数是数据列表。测试方法会为每组数据执行一次。

3. **Allure集成**：使用`@allure.feature`和`@allure.story`对测试用例进行分类，使用`with allure.step()`描述测试步骤，使生成的报告结构清晰、可读性强。

4. **断言设计**：根据预期结果（`expect_has_result`）执行不同的断言逻辑，覆盖有结果和无结果两种场景。断言失败时会自动截图，便于问题定位。

### 3.2 问题与解决方案

#### 问题一：元素定位不稳定导致测试失败

**问题描述：**

在编写测试脚本过程中，遇到了元素定位不稳定的问题。最初使用XPath绝对路径定位元素（如`/html/body/div[2]/div[1]/a`），这种定位方式在页面结构发生微小变化时就会失效，导致测试用例失败。

**分析过程：**

1. 豆瓣网站的DOM结构较为复杂，元素的层级较深
2. 使用绝对XPath路径过于脆弱，无法适应页面微调
3. 部分元素的class属性包含动态内容（如随机生成的ID）

**解决方案：**

1. **优先使用稳定的定位策略**：
   - 使用ID定位（最稳定）：`(By.ID, "inp-query")`
   - 使用CSS Selector定位：`(By.CSS_SELECTOR, ".search-button")`
   - 使用XPath相对路径定位：`//a[contains(@href,'/tag/文学')]`

2. **使用显式等待替代固定等待**：
   ```python
   # 改用 WebDriverWait 显式等待
   element = WebDriverWait(driver, 10).until(
       EC.visibility_of_element_located((By.ID, "inp-query"))
   )
   ```

3. **添加元素存在性检查**：
   ```python
   def is_element_visible(self, locator):
       """判断元素是否可见，不存在也不抛异常"""
       try:
           element = self.driver.find_element(*locator)
           return element.is_displayed()
       except:
           return False
   ```

**实施效果：**

修改后，测试用例的稳定性大幅提升，即使豆瓣网站进行小幅改版，测试脚本也能正常运行，只需要针对性地修改受影响的元素定位器即可。

#### 问题二：数据驱动中JSON数据读取路径问题

**问题描述：**

在PyCharm中直接运行测试时，`data_reader.read_json()`能够正确找到JSON文件，但在命令行或其他目录运行时，会报文件找不到的错误。

**分析过程：**

1. 相对路径是相对于当前工作目录（CWD），而不是相对于Python文件所在目录
2. 从不同位置运行pytest时，当前工作目录可能不同
3. JSON数据文件位于`data/`目录，但相对路径解析时可能指向错误位置

**解决方案：**

1. **统一使用基于项目根目录的绝对路径**：
   ```python
   # 在 config.py 中定义
   import os
   PROJECT_ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
   DATA_DIR = os.path.join(PROJECT_ROOT, 'data')
   LOG_DIR = os.path.join(PROJECT_ROOT, 'logs')
   ```

2. **在conftest.py中添加路径自动配置**：
   ```python
   import sys
   from pathlib import Path

   # 自动将项目根目录添加到 Python 路径
   _current_file = Path(__file__).resolve()
   _project_root = _current_file.parent
   if str(_project_root) not in sys.path:
       sys.path.insert(0, str(_project_root))
   ```

3. **数据读取方法改进**：
   ```python
   def read_json(file_name):
       """读取JSON测试数据文件"""
       import json
       file_path = os.path.join(config.DATA_DIR, file_name)
       with open(file_path, 'r', encoding='utf-8') as f:
           return json.load(f)
   ```

**实施效果：**

无论从哪个目录运行pytest，测试数据都能正确加载，项目在不同开发环境和CI/CD环境中都能正常运行。

#### A.1 BasePage 基类（base_page.py）

```python
"""
BasePage 基类
封装 Selenium 常用操作，所有页面对象类都继承此类
"""
import time
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC
from selenium.common.exceptions import TimeoutException

from common.config import TIMEOUT
from common.logger import get_logger


class BasePage:
    """
    页面基类
    封装了 Selenium 的常用操作，如元素定位、点击、输入、截图等
    所有具体页面类都继承自此类
    """

    def __init__(self, driver):
        self.driver = driver
        self.wait = WebDriverWait(driver, TIMEOUT)
        self.logger = get_logger()

    def wait_element_visible(self, locator):
        """等待元素可见"""
        try:
            element = self.wait.until(EC.visibility_of_element_located(locator))
            return element
        except TimeoutException as e:
            self.logger.error(f"等待元素可见失败：{locator}")
            raise

    def wait_element_clickable(self, locator):
        """等待元素可点击"""
        try:
            element = self.wait.until(EC.element_to_be_clickable(locator))
            return element
        except TimeoutException as e:
            self.logger.error(f"等待元素可点击失败：{locator}")
            raise

    def find_element(self, locator):
        """查找单个元素，先等待再查找"""
        try:
            element = self.wait_element_visible(locator)
            return element
        except Exception as e:
            self.logger.error(f"查找元素失败：{locator}")
            raise

    def find_elements(self, locator):
        """查找多个元素"""
        try:
            elements = self.wait.until(EC.presence_of_all_elements_located(locator))
            return elements
        except TimeoutException as e:
            self.logger.error(f"查找多个元素失败：{locator}")
            raise

    def click(self, locator):
        """点击元素，先等待可点击再点击（自动处理安全验证）"""
        try:
            element = self.wait_element_clickable(locator)
            element.click()
            time.sleep(1)
            self._handle_security_check()
        except Exception as e:
            self.logger.error(f"点击元素失败：{locator}")
            raise

    def input_text(self, locator, text):
        """输入文本，先等待可见再清除再输入"""
        try:
            element = self.wait_element_visible(locator)
            element.clear()
            element.send_keys(text)
        except Exception as e:
            self.logger.error(f"输入文本失败：{locator}")
            raise

    def get_text(self, locator):
        """获取元素文本"""
        try:
            element = self.wait_element_visible(locator)
            return element.text
        except Exception as e:
            self.logger.error(f"获取元素文本失败：{locator}")
            raise

    def open_url(self, url):
        """打开指定 URL（自动处理豆瓣安全验证）"""
        try:
            self.driver.get(url)
            self._handle_security_check()
        except Exception as e:
            self.logger.error(f"打开 URL 失败：{url}")
            raise

    def _handle_security_check(self):
        """自动检测并处理豆瓣安全验证页面"""
        try:
            current_url = self.driver.current_url
            if "sec.douban.com" in current_url or "安全验证" in self.driver.title:
                self.logger.info("检测到豆瓣安全验证页面，尝试自动处理...")
                # 尝试多套定位器找到"点我继续浏览"按钮
                button_selectors = [
                    ("xpath", "//button[contains(text(), '继续浏览')]"),
                    ("xpath", "//a[contains(text(), '继续浏览')]"),
                ]
                from selenium.webdriver.common.by import By as By2
                for by, selector in button_selectors:
                    try:
                        by_attr = by.upper().replace('CSS SELECTOR', 'CSS_SELECTOR')
                        elements = self.driver.find_elements(getattr(By2, by_attr), selector)
                        for btn in elements:
                            if btn.is_displayed() and "继续" in btn.text:
                                btn.click()
                                time.sleep(2)
                                return True
                    except Exception:
                        continue
                return False
        except Exception as e:
            self.logger.debug(f"检查安全验证时出错（可忽略）：{e}")
        return False

    def get_title(self):
        """获取页面标题"""
        return self.driver.title

    def is_element_visible(self, locator):
        """判断元素是否可见"""
        try:
            self.wait_element_visible(locator)
            return True
        except TimeoutException:
            return False
```

```python
        (By.CSS_SELECTOR, "div.item"),
        (By.CSS_SELECTOR, ".article li"),

        (By.CSS_SELECTOR, "li.book-item"),
    ]

    def get_category_title(self):
        """获取分类标题（快速检查，不等待超时）"""
        for selector in self.category_title_selectors:
            try:
                elements = self.driver.find_elements(*selector)
                if elements and elements[0].is_displayed():
                    text = elements[0].text.strip()
                    if text:

            except Exception:

        """获取当前页图书列表数量（快速检查）"""
        for selector in self.book_list_selectors:
            try:
                elements = self.driver.find_elements(*selector)
                if elements and elements[0].is_displayed():
                    return len(elements)
            except Exception:
                continue
        return 0

    def wait_for_page_load(self, keyword=None, timeout=8):
        """等待分类页加载完成（自动处理标签列表页跳转）"""
        start_time = time.time()
        clicked_tag = False
        while time.time() - start_time < timeout:
            # 检查是否有图书列表
            for selector in self.book_list_selectors:
                try:
                    elements = self.driver.find_elements(*selector)
                    if elements and elements[0].is_displayed():
                        return True
                except Exception:
                    continue
            # 检查是不是标签列表页，如果是就点击具体标签
            if not clicked_tag and keyword:
                try:
                    if "豆瓣图书标签" in self.driver.title:
                        tag_selectors = [
                            (By.XPATH, f"//a[contains(text(), '{keyword}')]"),
                            (By.LINK_TEXT, keyword),
                        ]
                        for by_sel in tag_selectors:
                            tag_links = self.driver.find_elements(*by_sel)
                            for link in tag_links:
                                if link.is_displayed() and keyword in link.text:
                                    link.click()
                                    clicked_tag = True
                                    time.sleep(2)
                                    break
                            if clicked_tag:
                                break
                except Exception:
                    pass
            time.sleep(0.5)
        return False

    def is_category_page_displayed(self):
        """判断分类页是否正确加载"""
        return bool(self.get_category_title())
```

```python
"""
```

```python
import logging
import os
from datetime import datetime
from common.config import LOG_DIR

_logger_instance = None


def get_logger():
    """获取 logger 实例，单例模式"""
    global _logger_instance
    if _logger_instance is not None:
        return _logger_instance

    logger = logging.getLogger("autotest")
    logger.setLevel(logging.DEBUG)
    logger.propagate = False

    # 日志格式
    formatter = logging.Formatter(
        "%(asctime)s - %(levelname)s - %(filename)s:%(lineno)d - %(message)s"
    )

    # 控制台输出
    console_handler = logging.StreamHandler()
    console_handler.setLevel(logging.DEBUG)
    console_handler.setFormatter(formatter)
    logger.addHandler(console_handler)

    # 文件输出
    if not os.path.exists(LOG_DIR):
        os.makedirs(LOG_DIR)
    log_file_name = f"autotest_{datetime.now().strftime('%Y%m%d')}.log"
    log_file_path = os.path.join(LOG_DIR, log_file_name)
    file_handler = logging.FileHandler(log_file_path, encoding="utf-8")

    file_handler.setFormatter(formatter)
```
